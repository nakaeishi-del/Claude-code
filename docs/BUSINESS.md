# tomomeet 事業計画メモ

## 1. マネタイズモデル（食べログ型 PR枠）

### 実装済みの収益基盤
| 機能 | 説明 |
|---|---|
| PR枠（premium / standard） | `lib/restaurants.ts` の `sponsorPlan`。premiumは最上位表示＋ハイライトカード、standardは優先表示 |
| エンゲージメント計測 | `POST /api/track` — impression / detail / outbound / propose の4段階ファネル |
| 広告主レポート | `GET /api/admin/sponsor-stats?secret=<ADMIN_SECRET>` — 30日間のファネル数値と転換率。掲載枠の営業・更新提案に使う |
| 送客リンク | お店詳細シートの「お店のページ↗」(`externalUrl`)。アフィリエイトURL（食べログ/ホットペッパー/ぐるなびAPI提携 or バリューコマース経由）に差し替えるだけで送客報酬が発生する構造 |
| PR表記 | ステマ規制（2023年10月〜景表法）対応。有料枠には必ず「PR」ラベルを表示 |

### 料金プラン案（掲載店舗向け）
| プラン | 月額 | 内容 |
|---|---|---|
| Standard | ¥9,800 | 提案リスト優先表示・PR表記 |
| Premium | ¥29,800 | 最上位固定＋ハイライトカード＋月次レポート |
| 送客成果報酬 | 1件¥300〜500 | outbound クリック単価 or 予約成立ベース |

**営業トーク**: 「あなたのお店が『友達同士がこれから行く店を決める瞬間』に表示されます」— 検索型（食べログ）より購買意図が強いタイミングを売る。

### 立ち上げ手順
1. `ADMIN_SECRET` を Vercel 環境変数に設定
2. まず地元3〜5店舗に無料掲載を持ちかけてレポート実績を作る
3. レポートの数字（表示→提案転換率）を武器に有料化

## 2. 未実装・次に作るべき機能（優先順）

1. **プッシュ通知（Web Push）** — 投票依頼・確定通知。リテンションに直結。次スプリント最優先
2. **予約導線** — 確定後に「このお店を予約する」→ ホットペッパーAPI連携。送客報酬の柱
3. **日程調整の外部共有** — 未登録ユーザーも投票できるゲスト投票（調整さん型）。バイラルループの起点
4. **グループアルバム** — 集まりの写真共有。思い出機能の拡張、滞在時間を伸ばす
5. **有料ユーザープラン** — グループ数無制限・過去履歴無制限（¥480/月）。広告と両輪

## 3. 別プロダクト構想（Claude活用で稼ぐ）

### 推奨: 「AI受託の生産ライン化」→ 縦型SaaS
勝ち筋は「汎用ツール」ではなく **特定業種の面倒事を丸ごと引き受ける縦型SaaS**。

| 案 | 内容 | 初期収益までの速さ |
|---|---|---|
| A. 店舗向けAI販促アシスタント | 飲食店のGoogleマップ/Instagram投稿・クチコミ返信を自動生成。tomomeetの営業先と同じ顧客に売れる（シナジー大） | ★★★ 月¥9,800×10店で黒字 |
| B. LP/HP即日制作サービス | Claude Codeで「ヒアリング→当日納品」を売りに。制作¥50,000＋保守¥5,000/月 | ★★★ 受注型なので最速 |
| C. 業務マニュアルAI化SaaS | 中小企業の属人ノウハウをアップ→AIが新人質問に回答。導入¥100,000＋月額 | ★★ 営業サイクル長いがLTV大 |

**推奨シーケンス**: B（即金・実績作り）→ A（tomomeet店舗営業と同時展開）→ 顧客の声からCへ。
共通資産: どれも「Claude API + Next.js + Vercel」で、tomomeetのコードベース（認証・課金・管理画面）を流用できる。

### 次のアクション
1. tomomeetを公開し、店舗営業のときにAの構想も一緒にヒアリング
2. Stripe連携の課金基盤を一度作る（全プロダクトで使い回す）
